  Bottom-anchored growth: With SizeToContent="Height", Avalonia grows the window downward from its Position (top-left anchor). For a taskbar flyout, the   
  bottom edge must stay fixed. The fix subscribes to BoundsProperty changes via GetObservable() — whenever the window height changes (settings open →      
  taller, settings close → shorter), SnapToTaskbar() recalculates Position.Y = workArea.Bottom - windowHeight - gap, keeping the bottom anchored. This is  
   the same technique Windows 11 uses for Action Center and notification flyouts.

  Summary

  Issues: Window positioned too high on launch (Bounds.Height was 0), and settings expansion grew downward behind the taskbar instead of upward.

  Fix — reactive bottom-anchoring in MainWindow.axaml.cs:
  - GetObservable(BoundsProperty).Subscribe() watches for any height change
  - When docked, every size change triggers SnapToTaskbar() which recalculates y = workArea.Bottom - windowHeight - gap
  - Window grows upward (bottom edge stays fixed above taskbar)
  - Works for: initial layout, settings open/close, state changes (7d section appearing/disappearing)
  - Initial snap deferred 50ms via DispatcherTimer.RunOnce to let SizeToContent compute
